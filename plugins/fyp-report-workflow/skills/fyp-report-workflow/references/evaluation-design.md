# 评估设计口径

写 Chapter 3、Chapter 4 或任何涉及测试、评分、招募的文字，一律以本文件的数字与流程为准。口径冲突时先向用户确认，再统一改动，不要在两处各写一套。

## 1. 三个测试

| 测试 | 角色 | 内容 | 是否给 AI 辅助 |
|---|---|---|---|
| Test A | pre-test 前测 | 基线，接触系统之前 | 不给 |
| Test B | post-test 后测 | 系统活动中练过的概念与 bug 类型 | 不给 |
| Test C | transfer test 迁移测试 | 同类过程、未见过的题目 | 不给 |

- Test B 与 Test C 都必须在不给 AI 辅助的条件下完成。允许模型出答案，测的就是模型的能力，不是学生的能力。
- Test C 是核心论断的决定性工具。只在 Test B 上升高可能只是记住了练过的题；Test C 上升才说明调试过程迁移到了新题。
- 形式为 Google Form，题干是短小的有错 Python 程序，每题要求完成与系统一致的四步。
- 题量：Test A 三题、Test B 三题、Test C 两题。三段合计约 30 分钟，其中 Test A 约 10 分钟、Test B 约 10 分钟、Test C 约 8 分钟。30 分钟指整场合计，不是每个测试各 30 分钟。
- 口径优先级：题量与时长以 `Chapter_3_Methodology\Integrated_Evaluation_Plan.md` 为准，其次是第三章正文，再次是总架构文档。三处已统一为 A 三题、B 三题、C 两题、合计 30 分钟。改动任一处时必须同步改其余两处。

## 2. 四维度评分 rubric

每题按四个维度各打 0 至 2 分，单题满分 8 分。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| Error Identification | 未识别或定位错误 | 部分识别或描述含糊 | 精确识别并定位正确 |
| Cause Explanation | 无解释或解释错误 | 捕捉部分机制但不完整 | 正确说明错误为何发生 |
| Code Correction | 未修正或仍报错 | 部分用例通过但不完整 | 修正后在隐藏测试用例上通过 |
| Verification | 未给验证 | 有验证但不确认行为 | 给出测试用例并正确确认结果 |

## 3. 混合评分模型

权威细节在 `Chapter_3_Methodology\Evaluation_Scoring_Procedure.md`。要点：

- **Code Correction：** 全自动。提交的代码在隔离沙箱中跑隐藏测试用例，与 Online Python Tutor 类判题系统和 Bassner 的自动评分实践一致。
- **Error Identification：** 规则匹配加研究者复核。
- **Cause Explanation：** 两名专家按 0 至 2 rubric 独立评分，用 Cohen's kappa 衡量一致性，目标不低于 0.7，对应 HypoCompass 的双人评分做法。分歧时对rubric讨论后取共识分。
- **Verification：** 自动覆盖检查加研究者复核。
- **AI 绝不当最终评分者。** 用 LLM 去批改不给 AI 的测试，会污染正在测量的条件。

## 6. 与分析方法的衔接

- 样本小，以描述统计为主：频次、百分比、均值、中位数、标准差，隐藏用例通过率。
- 主要比较是 Test A 到 Test B、Test A 到 Test C 的变化。满足正态性假设用配对样本 t 检验，不满足用 Wilcoxon 符号秩检验，并报告效应量。
- 定性部分用内容分析处理书面解释与系统活动轨迹，主题与定量结果合并叙述，每个统计结论都配上解释它的证据。
- 不做超出样本能力的总体推断。
